# 节点创建菜单

## 设计原则

节点创建菜单由 `NodeMenuItem.MenuPath` 统一维护。菜单分组、菜单显示名以及静态节点的默认标题都来自这条完整路径，不再额外维护 `NodeCategory`，也不再从类名推导用户可见名称。

```csharp
[NodeMenuItem("数学/Add (Float)", Description = "计算两个浮点数之和")]
public class AddNode_Float : ShizukuValueNode
{
    // 没有动态标题需求时，无需覆写 Title。
}
```

- `/` 前的路径段是中文功能分组。
- 最后一段是可直接搜索的英文节点名，同时作为静态节点的默认标题。
- `Description` 是搜索项提示文本。
- `Order` 控制同一层级的排序，越小越靠前。
- 路径建议保持两层，例如 `逻辑/Branch`。

## 显示规则

`NodeSearchWindowProvider` 只收集同时满足以下条件的类型：

1. 继承自 `ShizukuNodeBase`；
2. 不是抽象类；
3. 显式标注了 `NodeMenuItem`，并提供非空 `MenuPath`。

未标注的类型不会按类名兜底进入菜单。因此根节点、事件入口和返回节点等内部结构节点可以保持无特性，并通过编辑器的受控入口创建。函数调用项根据当前图中的函数动态添加。

## 编辑器入口

在图的空白处打开右键菜单，使用 GraphView 的“创建节点”入口进入可搜索的节点树。普通节点不再同时维护一份硬编码右键菜单；右键菜单只保留根节点、蓝图事件、分组等需要上下文判断的操作。

## 新增节点检查清单

- `MenuPath` 是完整、简短的路径；
- 分组段只使用中文，最后一段只使用英文名称；
- 同一个完整路径只对应一个节点类型；
- 静态节点优先使用默认标题，只有变量名、属性名等运行时信息会变化时才覆写 `Title`；
- 不希望用户直接创建的内部节点不要添加 `NodeMenuItem`。
