# Blueprint Generator - 快速开始指南

## 功能概览

Blueprint Generator 是一个可视化管理工具，帮助你自动生成和管理蓝图类。

### 主要特性

✅ **自动扫描**：检测所有 `BlueprintBehavior<T>` 子类  
✅ **一键生成**：自动生成对应的 `ShizukuBluePrint<T>` 类  
✅ **批量操作**：支持批量生成所有缺失的蓝图类  
✅ **状态显示**：清晰显示哪些类已生成、哪些未生成  
✅ **路径管理**：显示生成文件的完整路径  
✅ **快速定位**：一键跳转到生成的脚本文件  
✅ **智能分析**：显示可重写方法数量、命名空间等信息

## 使用流程

### 1️⃣ 创建 Behavior 类

```csharp
using UnityEngine;

public class MyCharacterBehavior : BlueprintBehavior<MyCharacterBehavior>
{
    [SerializeField] protected float health = 100f;
    
    [BlueprintOverridable]
    protected virtual void OnDamaged(float damage)
    {
        if (TryExecuteBlueprintOverride(nameof(OnDamaged), damage))
            return;
        
        health -= damage;
        Debug.Log($"Took {damage} damage");
    }
}
```

**关键点**：
- 继承 `BlueprintBehavior<T>`，T 是类自身
- 使用 `[BlueprintOverridable]` 标记可重写的方法
- 在方法开头调用 `TryExecuteBlueprintOverride`

### 2️⃣ 打开 Blueprint Generator

`Shizuku → Blueprint Generator`

### 3️⃣ 生成蓝图类

**方式 A：单个生成**
1. 在列表中找到 `MyCharacterBehavior`
2. 点击 **[Generate]** 按钮
3. 等待生成完成提示

**方式 B：批量生成**
1. 点击顶部的 **[Generate All Missing]** 按钮
2. 在弹出的确认对话框中点击 **[Generate]**
3. 等待所有类生成完成

### 4️⃣ 验证生成结果

生成完成后，列表会自动刷新，显示：
- 状态变为 **✓ Generated**（绿色）
- 显示生成文件的路径
- 出现 **[Regenerate]** 和 **[Locate]** 按钮

### 5️⃣ 创建蓝图资源

1. 在 Project 窗口右键
2. 选择 `Create → Shizuku → Blueprint → MyCharacterBehavior Blueprint`
3. 命名并保存资源文件（例如：`PlayerBlueprint.asset`）

### 6️⃣ 在场景中使用

1. 创建 GameObject
2. 添加 `MyCharacterBehavior` 组件
3. 将创建的 Blueprint Asset 拖入 Blueprint 字段
4. 运行游戏测试

### 7️⃣ 编辑蓝图逻辑

1. 双击 Blueprint Asset
2. 在 Shizuku Graph 窗口中编辑可视化逻辑
3. 添加事件节点（如 `OnDamaged`）
4. 连接逻辑节点实现自定义行为

## 高级功能

### 重新生成蓝图类

如果 Behavior 类的签名发生变化（如添加/删除方法），可以：

1. 点击 **[Regenerate]** 按钮
2. 确认覆盖现有文件

⚠️ **警告**：重新生成会覆盖所有手动修改的代码！

### 定位脚本文件

点击 **[Locate]** 按钮可以：
- 在 Project 窗口中高亮显示脚本
- 自动选中该脚本文件

### 自定义初始化逻辑

生成的代码中包含注释模板，取消注释即可添加自定义逻辑：

```csharp
public override void InitializeBehavior(MyCharacterBehavior behavior)
{
    base.InitializeBehavior(behavior);
    
    // 自定义初始化
    Debug.Log("Blueprint initialized for: " + behavior.gameObject.name);
    
    // 可以在这里注册额外的事件或属性
}
```

## 命名约定

生成器遵循以下命名约定：

| 类型 | 命名规则 | 示例 |
|------|----------|------|
| Behavior 类 | `*Behavior` | `EnemyBehavior` |
| Blueprint 类 | `*Blueprint` | `EnemyBehaviorBlueprint` |
| Blueprint 文件 | `*Blueprint.cs` | `EnemyBehaviorBlueprint.cs` |
| CreateAssetMenu | `Shizuku/Blueprint/*` | `Shizuku/Blueprint/EnemyBehavior Blueprint` |

## 常见问题

### ❓ 为什么找不到我的 Behavior 类？

**可能原因**：
1. 类没有继承 `BlueprintBehavior<T>`
2. 类是 `abstract` 或 `interface`
3. 类的泛型参数 T 不是自身

**解决方法**：
- 点击 **[Refresh]** 按钮重新扫描
- 检查类定义是否正确

### ❓ 生成后找不到 CreateAssetMenu 选项？

**解决方法**：
1. 等待 Unity 编译完成（查看右下角进度条）
2. 刷新 Project 窗口（Ctrl+R）
3. 如果仍未出现，重启 Unity 编辑器

### ❓ 路径显示为空？

这是正常的，表示：
- 脚本文件名与类名不匹配
- 或者有多个同名类

**不影响功能**，可以手动搜索文件。

### ❓ 重新生成会丢失自定义代码吗？

**是的！** 重新生成会完全覆盖文件。

**建议**：
- 自定义逻辑放在 Behavior 类中
- 或者备份生成的 Blueprint 类再修改
- 或者不使用 Regenerate 功能

### ❓ 批量生成失败了怎么办？

查看 Unity Console 窗口的错误日志，通常是：
- 文件权限问题
- 路径过长
- 磁盘空间不足

解决后点击 **[Generate]** 单独生成失败的类。

## 最佳实践

### ✅ DO（推荐）

1. **在开发早期生成蓝图类**，避免后期批量操作
2. **使用有意义的类名**，如 `PlayerBehavior`、`EnemyBehavior`
3. **在 Behavior 类中保持逻辑清晰**，方便蓝图重写
4. **定期使用 Refresh** 确保列表最新

### ❌ DON'T（不推荐）

1. **不要手动修改生成的 Blueprint 类**（除非不再使用 Regenerate）
2. **不要在 Blueprint 类中编写复杂逻辑**（应该在蓝图编辑器中完成）
3. **不要频繁重命名 Behavior 类**（会导致 Blueprint 类失效）

## 技术细节

### 扫描机制

生成器会：
1. 遍历所有已加载的程序集
2. 跳过 Unity 和系统程序集
3. 查找继承 `BlueprintBehavior<T>` 的非抽象类
4. 检查泛型参数是否匹配

### 生成路径规则

**优先级 1**：与 Behavior 类相同的目录  
**优先级 2**：`Assets/Scripts/Graph/Blueprint/`

### 类型验证

生成器会验证：
- Blueprint 类是否继承 `ShizukuBluePrint<T>`
- 泛型参数 T 是否与 Behavior 类匹配
- 文件名是否符合命名约定
